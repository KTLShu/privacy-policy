🍃 一叶文件秒搜 · 隐私政策

100% 本地运算 · 零个人数据收集 · 纯净安全
生效日期：2026年10月29日 · 最近更新：2026年10月30日
核心隐私承诺：
【一叶文件秒搜】是一款纯本地运行的文件检索与管理工具。本应用不会收集、上传、存储或共享您的任何个人身份信息、文件内容、通讯录或搜索历史到任何远程服务器。所有文件索引与搜索运算均 100% 在您的设备芯片及本地存储内完成。

1. 我们如何处理您的数据

文件索引与本地运算：为了实现全盘毫秒级极速搜索，应用会在设备本地建立内存文件索引。所有索引数据、文件名、路径和时间戳均仅存储在您设备的临时内存或私有沙盒空间中，绝不会通过网络向外传输。

搜索历史与配置：您的历史搜索记录、展示上限、排序偏好等设置，均仅保存在您手机本地的 SharedPreferences 配置文件中，随应用卸载自动销毁。

2. 设备权限使用说明

为了实现核心的文件检索与操作功能，应用可能会申请以下系统权限，我们在此对每项权限的用途作清晰透明的声明：

所有文件访问权限 (MANAGE_EXTERNAL_STORAGE)
必要核心权限：作为文件管理与全局搜索工具，应用需要遍历设备公共存储空间以建立全盘文件索引，让您能够即时检索所有目录下的文件与文档。此权限绝不用于检索之外的任何未授权操作。
安装未知应用权限 (REQUEST_INSTALL_PACKAGES)
用户交互权限：当您在搜索结果中点击 APK 安装包文件时，该权限用于唤起 Android 系统原生安装器帮助您完成应用安装。应用不会在后台静默下载或自动安装任何程序。
查询所有软件包权限 (QUERY_ALL_PACKAGES)
体验增强权限：当您检索或浏览 /Android/data/包名 等应用目录时，用于匹配并展示该目录所属应用程序的人性化名称和图标，帮助您直观识别文件归属。

3. 第三方 SDK 与数据服务声明

为了保障软件运行的稳定性、持续优化用户交互体验以及及时下发重要配置，在 Google Play 发布的版本中集成了 Google 官方提供的 Firebase SDK 套件（国内渠道版本完全隔离并移除了相关 Google 远程组件）：

Google Firebase Crashlytics（异常崩溃监控）
  • 使用目的：实时捕获应用在运行过程中的崩溃异常与未响应（ANR）日志，帮助开发者快速定位代码缺陷并提升软件稳定性。
  • 数据收集范围：设备机型、操作系统版本、应用版本、崩溃堆栈跟踪信息、设备状态（如可用内存与存储空间大小）。
  • 隐私边界：绝不收集任何用户身份信息、网络硬件地址（MAC/IMEI）或设备中的任何文件内容与文件名。
Google Firebase Analytics（匿名用户分析与统计）
  • 使用目的：统计应用的日常活跃指标与核心功能使用频次，用于指导产品性能迭代与界面体验改进。
  • 数据收集范围：匿名应用实例标识符（Firebase App Instance ID）、标准设备技术参数（系统语言、屏幕分辨率、操作系统版本）、匿名聚合的功能交互事件。
  • 隐私边界：严格禁止并杜绝收集用户具体的搜索关键词、搜索历史、本地文件路径、文件内容或任何可识别用户真实身份的个人数据。
Google Firebase Remote Config（远程参数与动态配置）
  • 使用目的：用于动态下发应用公告、合规与版本更新提示、性能优化参数与功能开关，无需频繁重新发版即可快速响应兼容性调整。
  • 数据交互：仅在应用启动或配置刷新时，向 Firebase 服务器拉取最新的只读参数键值对。不收集或回传用户本地隐私数据。

上述 Google Firebase 服务均严格遵循 Google 隐私权政策 及 Google Play 开发者分发协议。

🍃 Leaf Fast Search · Privacy Policy

100% Local Processing · Zero Personal Data Collection
Effective Date: October 29, 2026 · Last Updated: October 30, 2026
Our Privacy Commitment:
Leaf Fast Search is a standalone, local-first file indexing and management utility. We do NOT collect, upload, store, or share any personal identifiable information, file contents, contacts, or search histories to external servers. All search indexing and computations are performed 100% locally on your device.

1. Data Handling & Security

Local Indexing: To deliver sub-second search speeds across internal storage, the app builds an in-memory index of file metadata. All index data resides solely in local device memory and is never transmitted over the internet.

Preferences & Search History: Your search filters and display preferences are stored exclusively on your device via standard Android private storage and are deleted upon app uninstallation.

2. App Permissions & Justification

All Files Access (MANAGE_EXTERNAL_STORAGE)
Core Functional Requirement: As a file manager and search utility, this permission is strictly necessary to traverse and index files across your device storage so that users can instantly locate documents, archives, and media.
Install Unknown Apps (REQUEST_INSTALL_PACKAGES)
User-Initiated Action: Allows the app to hand over APK files to the system Package Installer when explicitly tapped by the user. No background installations are ever performed.
Query All Packages (QUERY_ALL_PACKAGES)
UI Enhancement: Used solely to match and display friendly application labels and icons for directories under /Android/data/<package_name>, assisting users in recognizing folder origins.

3. Third-Party SDKs & Services (Google Firebase)

For Google Play releases, we integrate the official Google Firebase SDK Suite strictly to ensure application stability, understand aggregated usage patterns to improve performance, and deliver dynamic runtime configuration. (Domestic/China releases are completely isolated from these Google cloud services):

Google Firebase Crashlytics (Crash Reporting)
  • Purpose: Diagnosing unhandled exceptions, app crashes, and Application Not Responding (ANR) events to ensure high reliability.
  • Data Collected: Non-personally identifiable diagnostic data including device model, OS version, app version, stack traces, and device memory state at the moment of crash.
  • Privacy Safeguard: Does not collect personal identity, hardware identifiers (IMEI/MAC), or local file metadata.
Google Firebase Analytics (Aggregated Product Analytics)
  • Purpose: Gauging general app active metrics and aggregate feature interactions to guide UI enhancements and performance optimizations.
  • Data Collected: Anonymous Firebase instance identifiers, standard technical device attributes (language, screen resolution, OS version), and aggregated in-app interaction events.
  • Privacy Safeguard: Strictly prohibited from capturing users' specific search keywords, queries, search history, file contents, or personal identifiers.
Google Firebase Remote Config (Dynamic App Configuration)
  • Purpose: Retrieving up-to-date configuration flags, policy update announcements, and runtime feature toggles without requiring repeated app rebuilds.
  • Data Interaction: Synchronizes standard read-only configuration keys from Firebase servers upon launch. No personal or storage data is transmitted.

All Google Firebase services operate under the Google Privacy Policy.
